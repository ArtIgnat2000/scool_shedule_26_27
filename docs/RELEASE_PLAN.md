## 2. Разбор требований

### Т1. Динамическая загрузка расписания из текстового файла

- Все данные выносятся в каталог `data/` и грузятся при открытии страницы.
- **Рекомендуемый формат — JSON** (`data/class-2v.json`, `data/class-4b.json`): надёжный парсинг, вложенные структуры (дни → уроки → время/предмет/кабинет), понятен и человеку.
  Альтернатива — простой TXT с разделителями («Пн; 1; 8:30–9:10; Математика»), если файл будут править руки, далёкие от JSON. Можно поддержать оба формата одним парсером.
- ⚠️ Ограничение: `fetch()` не работает при открытии файла двойным кликом (`file://`). Нужен локальный сервер (`python -m http.server`) или GitHub Pages — на проде проблемы нет. Отразить в README.
- Плюс: расписание правится без единой строчки кода — просто редактированием файла в GitHub прямо из браузера/телефона.

### Т2. Выбор класса: 2«В» и 4«Б»

- Переключатели класса и системы обучения вынесены на отдельную страницу `settings.html`, чтобы не перегружать шапку главной.
- Каждому классу — свой файл данных: `data/class-2v.json`, `data/class-4b.json`.
- Список классов — тоже из файла (`data/classes.json`), чтобы добавление 5-го класса не требовало правки кода.
- Выбор сохраняется в `localStorage` — при следующем визите открывается «свой» класс.
- Поддержка deep-link: `index.html?class=4b` — можно дать родителям прямую ссылку.

### Т3. Каникулы — календарь по месяцам

- Страница `holidays.html` внутри этого же репозитория (вместо внешней ссылки на `RaspisCanicyl`).
- Календарная сетка на учебный год (сентябрь 2026 — май 2027): помесячно, строки — недели (Пн–Вс), как в обычном календаре. Последний учебный день: 26.05.2027 по четвертям или 31.05.2027 по триместрам.
- Периоды каникул и праздники — из файла `data/holidays.json`: осенние 26.10–03.11.2026, зимние 31.12.2026–10.01.2027, весенние 27.03–04.04.2027, летние с 27.05.2027; календарь отображается с 01.09.2026 по 31.05.2027.
- **Правила раскраски:**
  - учебный день — чёрный текст на белом фоне;
  - суббота/воскресенье и гос. праздники — красный текст;
  - дни каникул — зелёный фон;
  - сегодняшний день — выделен (кольцо/точка, как в iOS Calendar).
- Календарь генерируется JS автоматически по датам — никакой ручной вёрстки 12 месяцев. Клик по цветной карточке каникул прокручивает к соответствующему месяцу и выделяет дни периода.

### Т4. Персональные страницы учеников

- Страница `student.html?id=ivanov` + файлы `data/students/<id>.json`.
- Содержимое персонального файла: доп. уроки, тренировки, секции — по всем 7 дням недели, включая Сб/Вс.
- На странице объединяются два слоя: базовое расписание класса ученика + его личные занятия (визуально различимы: уроки — один стиль карточек, секции/тренировки — другой, с иконкой вида активности).
- Список учеников — `data/students/index.json`; на главной — переход «Моё расписание».
- ⚠️ Приватность: репозиторий публичный — использовать только имя/инициалы, без фамилий и личных данных, либо «непрозрачные» id в ссылках.

### Т5. Дизайн iOS 26

- Строгая светлая основа (system gray background), карточки с «liquid glass» эффектом: полупрозрачность + `backdrop-filter: blur()`, крупные радиусы скругления (16–24px), тонкие разделители.
- Типографика в духе SF Pro: системный шрифт (`-apple-system, "SF Pro Text", Inter, Segoe UI`), крупные жирные заголовки (Large Title), сдержанная палитра — акцентный синий #0A84FF, системные red/green для календаря.
- Сегмент-контролы вместо разноцветных кнопок, списки-«inset grouped» вместо таблиц с рамками.
- Убрать облака, градиентное небо и избыточные тени — «стильно и строго».
- Тёмная тема через `prefers-color-scheme` (даётся почти бесплатно при работе через CSS-переменные).

## 3. Целевая структура репозитория

```
schedule/
├── index.html            # расписание уроков
├── holidays.html         # календарь каникул
├── student.html          # персональная страница ученика
├── settings.html         # настройки класса и системы обучения
├── meal.html             # расписание питания
├── css/style.css         # единая дизайн-система iOS 26
├── js/
│   ├── data.js           # загрузка и парсинг файлов данных
│   ├── schedule.js       # рендер расписания
│   ├── calendar.js       # генератор календаря
│   ├── settings.js       # сохранение настроек профиля
│   ├── meal.js           # расписание питания
│   └── student.js        # персональные страницы
└── data/
    ├── classes.json      # список классов
    ├── class-2v.json     # расписание 2«В»
    ├── class-4b.json     # расписание 4«Б»
    ├── holidays.json     # каникулы и праздники
    ├── meal.json         # расписание питания
    └── students/
        ├── index.json
        └── <id>.json     # личные занятия ученика
```

Пример формата данных класса:

```json
{
  "class": "2В",
  "days": {
    "mon": [
      { "n": 1, "time": "8:30–9:10", "subject": "Математика", "icon": "🧮" }
    ]
  }
}
```

## 5. ЭТАП 2 — дополнительные возможности (v2.1+)

### Приоритет A — быстрые и полезные
1. **«Сейчас идёт урок»** — автоопределение текущего дня и подсветка текущего/следующего урока по времени (главная «wow»-фишка для ежедневного использования).
2. **Автооткрытие сегодняшнего дня** — при заходе активен текущий день недели, а не всегда Пн.
3. **Счётчик до каникул** — «До каникул осталось 12 учебных дней» на календаре.
4. **Тёмная тема** — авто по системной настройке + ручной переключатель.
5. **Интеграция «ЕДА» и «ДОП»** — перенести меню и доп. занятия в этот же репозиторий на общий слой данных и дизайн (сейчас 3 разных репозитория с разным видом).

### Приоритет B — развитие продукта
6. **PWA** — manifest + service worker: установка на домашний экран как приложение, работа офлайн (расписание кешируется).
7. **Домашние задания** — файл `homework.json`, вкладка «ДЗ» с датами сдачи.
8. **Уведомления** — напоминание «завтра бассейн — взять форму» (заметки-напоминания к дням недели из файла данных).
9. **Экспорт в календарь (.ics)** — кнопка «Добавить в календарь телефона» для секций и каникул.
10. **Печатная версия** — CSS `@media print`: расписание на неделю одним листом А4 на холодильник.

### Приоритет C — стратегические
11. **Мини-админка** — страница-редактор, которая формирует JSON визуально (для учителя/родителя без навыков разработки); сохранение через GitHub API или скачивание файла.
12. **Числитель/знаменатель** — поддержка чередующихся недель, если появится в старших классах.
13. **Мультишкольность** — конфиг `school.json` (название, звонки, учебный год) — проект превращается в шаблон, который может развернуть любая школа.
14. **Статистика/дневник** — связка с таблицей оценок (уже есть зачаток в `rating`): личный прогресс ученика.

**Текущий прогресс рабочей версии v2.1.0:** реализованы автоматический текущий день, подсветка текущего и следующего урока, статус дня, счётчик до ближайших каникул, кликабельные периоды каникул и переключатель «по четвертям / по триместрам». Даты триместров пока демонстрационные.

Интеграция «ЕДА» завершена: страница перенесена в основной проект, данные вынесены в `data/meal.json`, навигация обновлена. Следующим шагом v2.1.0 остаётся интеграция «ДОП».

**v2.2.0:** страница «Моё» (`student.html`) удалена — выбор ученика перенесён в настройки (⚙️ → «Ученик»), а личные занятия выбранного ученика показываются на главной странице «Уроки» под уроками класса (дни недели расширяются до Пн–Вс, если у ученика есть занятия на выходных). Навигация сократилась до трёх разделов: Уроки · Каникулы · Еда. PWA и ДЗ — следующий релиз.

## 6. Риски и замечания

- **`file://` и fetch** — динамическая загрузка требует HTTP; для локальной проверки — `python -m http.server` (уже описан в README), прод на GitHub Pages работает из коробки.
- **Персональные данные детей** в публичном репозитории — только имена/инициалы или обезличенные id.
- **Актуальность дат каникул** — файл `holidays.json` нужно обновлять раз в год; формат сделать так, чтобы это занимало 5 минут.
- **Обратная совместимость ссылок** — у родителей могут быть сохранены ссылки на `RaspisCanicyl`/`DopSchedule`; в старых репозиториях оставить редирект на новые страницы.
